A visual guide to Kubernetes

Kubernetes, drawn step by step.

Eight lessons: diagrams to read, and four labs you can operate.

New words. kubectl is the command you type. The control plane decides what should run where. Nodes are the machines that run your containers. A pod is one running copy of your app.

Start with how it worksOr break a pod

Why bother

  • It keeps what you asked for

    You write down the state you want. Controllers compare it with reality, forever, and fix the difference.

  • Pods come and go

    A Service gives a changing set of pods one stable address, so nothing else has to track them.

  • Updates without a gap

    A rolling update swaps old pods for new ones a few at a time, so there is always something serving.

Three commands to start

With a local cluster (the Practice lesson shows how) and the YAML from the Deploy lesson saved as app.yaml:

kubectl apply -f app.yaml
kubectl get pods
kubectl scale deployment/simple-app --replicas=3
