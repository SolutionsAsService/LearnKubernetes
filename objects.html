Objects

Everything in Kubernetes is an object you describe in YAML. Four of them carry most of the load.

Who owns whom

ObjectWhat it isYou usually
PodOne or more containers that share a network address and storageLet something else create it
ReplicaSetKeeps a stated number of identical pods runningLet a Deployment manage it
DeploymentA ReplicaSet plus an update strategy and historyWrite this
ServiceA stable address for a set of pods chosen by labelWrite this
NamespaceA named scope that groups objectsUse to separate teams or environments
ConfigMap, SecretConfiguration and sensitive values kept outside the imageMount or inject into pods

Labels are the glue

A label is a key and a value on an object, such as app: web. A selector picks objects by label. A Deployment finds its pods that way, and so does a Service. Nothing is wired by name.

Try it. In the Services lab, flip a pod's label and watch it drop out of the Service.
Common mistake. A selector that matches nothing. The object is created, nothing complains, and no traffic arrives. Check that the labels in the pod template and the selector are identical.
