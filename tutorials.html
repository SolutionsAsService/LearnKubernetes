Practice

Reading gets you the vocabulary. A cluster on your own machine gets you the rest.

A cluster on your laptop

You need a container runtime such as Docker or Podman, and kubectl. Then either of these makes a one-node cluster:

kind create cluster        # Kubernetes in Docker
# or
minikube start             # a local VM or container

kubectl get nodes          # you should see one node, Ready

A path through the lessons

  1. Apply the DeploymentSave the YAML from Deploy and run kubectl apply -f.
  2. Kill a podRun kubectl delete pod on one, then kubectl get pods -w. Compare with the lab.
  3. Scale to 3Change replicas, apply again, and see where the pods land with kubectl get pods -o wide.
  4. Reach itCreate the Service from Services and run kubectl port-forward svc/simple-app-service 8080:80.
  5. Update itChange the image tag and watch kubectl rollout status. Then undo it.

kubectl cheat sheet

CommandWhat it does
kubectl get podsList pods. Add -o wide for nodes, -w to watch
kubectl describe pod NAMEDetails and recent events for one pod
kubectl logs NAMEThe container's output
kubectl apply -f FILECreate or update from a file
kubectl delete -f FILEDelete what a file describes
kubectl scale deployment/NAME --replicas=NChange the replica count
kubectl rollout status deployment/NAMEWait for an update to finish
kubectl rollout undo deployment/NAMEGo back one revision
kubectl port-forward svc/NAME 8080:80Reach a Service from your machine
Common mistake. Running commands against the wrong cluster. Check with kubectl config current-context before you delete anything.
