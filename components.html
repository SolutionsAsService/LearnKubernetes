Architecture

A cluster is a control plane that decides and a set of nodes that do the work. Pick a part to see where it sits and what it does.

Pick a component

Turn on JavaScript to pick a part. The diagram below names every component; the table after it says what each does.

Who does what

ComponentRuns onJob
kube-apiserverControl planeThe front door for kubectl and every other component
etcdControl planeStores all cluster state
kube-schedulerControl planeChooses a node for each new pod
kube-controller-managerControl planeRuns the reconcile loops
kubeletEvery nodeStarts and watches the pods assigned to its node
kube-proxyEvery nodeMakes Service addresses reach pods
Container runtimeEvery nodeRuns the containers (containerd, CRI-O)
Common mistake. Picturing the components calling each other. They almost never do: each one watches and updates the API server, and that is how they coordinate.
