Deploy an app

One YAML file says what you want. This lesson shows the file, then follows what happens when you apply it.

The Deployment

A Deployment that runs one copy of nginx. Read the comments; the rest is boilerplate you will recognise quickly.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: simple-app
  labels:
    app: simple-app
spec:
  replicas: 1             # how many pods you want
  selector:
    matchLabels:
      app: simple-app     # which pods this Deployment manages
  template:               # the pod it will create
    metadata:
      labels:
        app: simple-app   # must match the selector above
    spec:
      containers:
      - name: simple-app-container
        image: nginx:1.27 # pin a version, not :latest
        ports:
        - containerPort: 80

The Service

A Service that sends traffic to any pod labelled app: simple-app.

apiVersion: v1
kind: Service
metadata:
  name: simple-app-service
spec:
  selector:
    app: simple-app       # send traffic to pods with this label
  ports:
  - protocol: TCP
    port: 80              # the Service's port
    targetPort: 80        # the container's port
  type: ClusterIP         # reachable inside the cluster only

What happens when you apply it

kubectl apply -f app.yaml            # create or update what the file describes
kubectl get deployments,pods,svc      # see the objects it made
kubectl describe pod <pod-name>       # events explain why a pod is not starting

The repository also has the full commented example: KubernetesExample.yaml.

Common mistake. Using image: nginx:latest. The tag can change under you, so two pods from the same file can run different code. Pin a version.
