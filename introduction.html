How Kubernetes works

Kubernetes runs containers, but the idea that matters is smaller: you say what you want, and software keeps it true.

Desired state

Kubernetes is an open-source system for running containerized applications across many machines. You do not tell it do these steps. You describe the state you want, such as "three copies of this app, version 1.21", and Kubernetes works out the steps.

Try it. Open the Scaling lab, click any pod to kill it, and watch the loop put it back.

What it gives you

  • Scheduling

    New pods are placed on nodes that have room.

  • Self-healing

    A pod that dies is replaced. A node that disappears has its pods rescheduled.

  • Scaling

    Change a number to run more copies, or let an autoscaler change it.

  • Service discovery

    Pods find each other through stable names and load-balanced addresses.

  • Rollouts and rollbacks

    Update gradually, and go back if the new version is bad.

Common mistake. Thinking Kubernetes is a container runtime. It is the manager above the runtime: it decides what should run where, and asks a runtime such as containerd to run it.
