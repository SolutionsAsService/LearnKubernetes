Scaling and self-healing

Change one number and the cluster runs more copies. Kill a pod and the cluster notices.

Set the replicas

Activate any pod to kill it.

Turn on JavaScript to use the lab. The YAML below is the whole idea.

Desired replicas: 3.

A simplified model: pods are spread evenly. The real scheduler also weighs resource requests, constraints and spread rules.

The only change

spec:
  replicas: 3   # was 1; apply the file again and Kubernetes starts two more
kubectl scale deployment/simple-app --replicas=3   # the same change, from the command line
kubectl get pods -w                                   # watch the pods appear

Autoscaling

A HorizontalPodAutoscaler changes the replica count for you from a metric such as CPU use. It needs a metrics source installed in the cluster, and your pods need resource requests so a percentage means something.

Common mistake. Editing the number of pods by hand while an autoscaler owns it. The autoscaler will change it back. Set the bounds, not the count.
